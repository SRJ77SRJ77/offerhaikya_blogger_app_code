errors

Diagnosing a device registration error from push notifications.

This isn't a bug in your sending code. DeviceNotRegistered means FCM no longer recognizes the device token you sent to. Expo accepted the push (you got a ticket ID), but delivery failed when it reached FCM.

Common causes

The app was uninstalled or its data was cleared.
The token was rotated or expired. Android tokens change after a reinstall, a restore, or long inactivity.
The token is stale: it's stored in your DB but the user has since got a new one.
It's a dev or test token, for example from an old build, an emulator, or a different app variant, that's now invalid.
Less commonly, the token was issued under a different Firebase project or credentials than the ones configured for this build.

What to do

Delete that token from your database and stop sending to it. Expo's docs say not to retry on this error.
Re-register tokens on every app launch. Call getExpoPushTokenAsync() (with your projectId) at startup and upsert it to your backend, so a rotated token replaces the old one.
Process receipts automatically. Check them roughly 15 minutes after sending and prune tokens that fail:
js
for (const [id, receipt] of Object.entries(receipts.data)) {
  if (receipt.status === 'error' && receipt.details?.error === 'DeviceNotRegistered') {
    await db.pushTokens.deleteByReceiptId(id); // map receipt/ticket ID → token when you send
  }
}

This requires storing the ticket-to-token mapping when you send, so you know which token each receipt belongs to.

If this happens for every device, not just one, check that your FCM credentials (service account key) are uploaded correctly in EAS and match the Firebase project in the app's google-services.json.
